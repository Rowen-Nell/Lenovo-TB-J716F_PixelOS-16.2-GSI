# Build

Linux Android build host with the dependencies required by the pinned PixelOS source. Supply legally available upstream prebuilt dependencies through their own projects; this source-only candidate does not redistribute them. Initialize Repo using this directory's manifest.xml after choosing the public repository URL, then obtain the pinned sources. No new sync was performed for the delivered local build.

On a clean matching source tree: `python3 /path/to/candidate/apply.py /path/to/android`. The script verifies each affected repository HEAD, checks all patches before applying, and verifies all resulting content hashes. It never resets existing source changes. Preserve original file modes from patches and source snapshots.

Source default is HDR experiment disabled. To reproduce the tested configuration, make a recorded build-only edit in device/tb03/gsi/system.prop: change `ro.surface_flinger.tb04_legacy_hdr_gpu=false` to `true` and append one `persist.sys.tb04_hdr_ratio_cap=2`. Do not alter brightness/HBM/refresh/saturation/ramp/composition policy. Restore the ordinary source default after the build. The cap is an experimental limit, not panel capability.

PRODUCT_ENABLE_UFFD_GC=false must remain effective; OVERRIDE_ENABLE_UFFD_GC must be unset or false. Keep normal preoptimization enabled. Verify generated EnableUffdGc=false, an empty uffd_gc_flag.txt and concurrent-copying=true in the resulting OAT headers. Never copy older OAT files or disable ART verification. The wallpaper RRO uses existing Make BUILD_RRO_PACKAGE, --package-id 0x7e --allow-reserved-package-id and an explicit unchanged Google APK resource include/link dependency; build and verify that module before one normal complete systemimage build. Google APK signing is preserved. Set CUSTOM_BUILD_DATE to the actual build date/time YYYYMMDD-HHMM and BUILD_DATETIME to its epoch. For a new release date, update device/tb03/gsi/product.prop so the human-visible version uses the actual date; the delivered release is fixed in source-lock.json. `source build/envsetup.sh`; `lunch pixelos_tb03_arm64_ext4-bp4a-userdebug`; `m systemimage -j4` (adjust jobs to host memory). Use an independently empty OUT_DIR before the first build; USE_CCACHE=0 and a fresh GOCACHE under it. Do not copy any old output. The build output is $OUT_DIR/target/product/tb03_arm64/system.img, a raw ext4 image with normal AVB footer. New modules require a regenerated valid Soong/Make graph. Do not replace complete production linking with local objects, validation APKs or copied stale outputs.

Official candidate builds require the already fixed private j716f-beta-release-v1 keyset bound locally at device/tb03/gsi/signing/keys-private. Restore that authority from maintainer custody; never generate replacement keys as a build fallback. Public fingerprints and certificates are in signing-public/. Fork maintainers must supply their own separately generated authority and identify it as a different update domain. No private project key is provided. The retained build variant is userdebug (ro.debuggable=1); release signing does not imply hardened user-build or security acceptance. The recorded delivered build uses arm64 with arm secondary and normal signed/optimized Settings, services, Hall backend, framework/MTP and init consumers.

The local clean build initially exposed an upstream test_package absolute-OUT path restriction. Use a unique relative OUT_DIR under the checkout, such as out-r28-beta-clean, backed by a new empty directory (or a project-local symlink to it). Keep GOCACHE absolute and fresh. This path correction changes no ROM functionality. The actual build log and failed first invocation are retained in the private build handoff. Upstream BuildKeys() labels non-Lineage custom key directories dev-keys even when the signing authority is private project release keys; final certificate/public-key fingerprints establish signing, not the text label.
